# Guidance for Claude working in this repository

## What this project is

A portfolio project owned by José Miguel Antunes (Miguel; MSc AI student,
targeting ML/AI engineering roles). A cross-lingual RAG system over five EU
regulations: questions in any language, an English-only index, answers in the
user's language with article-level citations. It is built as a ladder: one
retrieval technique per rung, each measured on the same benchmark.

Read `docs/PLAN.md` first: milestones, what is done, acceptance criteria.
`docs/SPEC.md` is the system, `docs/EVAL.md` the measurement rules,
`docs/rungs/` one spec per rung.

## The rule that matters most

Miguel has to be able to explain every part of this in an interview. That
shapes how to work here:

- Prefer the simple, visible implementation over the clever or the wrapped
  one. BM25 is written by hand for this reason. Reach for a library when the
  mechanism is not the point (HTTP, HTML parsing, the web framework).
- Every rung ships with a note in `docs/defend/` explaining the idea, the
  result, and the questions an interviewer would ask.
- When finishing a rung, tell him what changed and why in plain language, and
  point him at what to read. Do not just report that tests pass.
- If he asks why something is the way it is, explain it; do not just change it.
- `docs/decisions/M*.md` are **his**. Supply the numbers and, if asked,
  questions to think about. Never write the note for him.

## Numbers

- Never write a metric that did not come from a file under `results/`. No
  estimates presented as results, no numbers from blog posts or model cards in
  the results table.
- Choose on dev. The test split is run once per rung, after its configuration
  is frozen. If that is broken, say so in the pull request.
- A rung that does not help stays in the table with its real numbers, and is
  left out of the default pipeline.
- The README table is generated by `eurlex report`. Never edit it by hand.
- Report per query language. The gap between English and the others is the
  result; a pooled number hides it.

## Language rule

Non-English legal text is never embedded, indexed or machine-translated. It
lives in the parallel table for showing citations and building the benchmark.
`build_chunks` refuses non-English units on purpose.

## Workflow

- One milestone per branch (`m<N>-<slug>`) and pull request. Do not start a
  milestone before the previous one meets its acceptance criteria.
- Lead-and-sub-agents: the lead model plans, updates the spec, reviews and
  integrates; Opus sub-agents implement against the spec and the `Retriever`
  interface. Give each sub-agent a disjoint set of files.
- Specs describe intent. Models and library APIs move: before implementing a
  rung, check current documentation and what models are current, and update the
  spec if it was wrong. Pin exact model revisions, and record them in every
  result file through `Retriever.describe()`.
- When a milestone introduces something new to Miguel (pgvector, rank fusion,
  cross-encoders, LangGraph), the pull request explains it in plain language.

## Code conventions

- Package code in `src/eurlex_rag/`, tests in `tests/`. Rungs are registered by
  name in `src/eurlex_rag/registry.py`.
- New rungs implement `eurlex_rag.retrieve.base.Retriever`. Do not change that
  interface without updating every retriever, the runner, the service and the
  docs.
- The core has no third-party dependencies. Optional ones stay optional:
  importing `eurlex_rag` must not require an embedding library, a database
  driver, FastAPI or LangGraph. Import them inside the function that needs
  them. LangGraph is used in `agent/` only.
- Unit tests download nothing and need no database or network. They use the
  synthetic corpus in `tests/conftest.py` and fakes for models. Tests that need
  the real thing are marked `slow`.
- Retrieval is scored at article level (`eurlex_rag.ids.article_level`).
- `data/raw/` and `data/processed/` are git-ignored and rebuilt with
  `eurlex ingest`. Model files and vectors go in `artifacts/` (git-ignored).
  `results/` and `data/gold/` are committed.
- Secrets live in `.env` (git-ignored). Never commit keys.

## Commands

    pip install -e ".[dev,serve,ingest]"   # development install
    pytest                                 # unit tests, no downloads
    ruff check . && ruff format --check .
    eurlex rungs                           # what can be run today
    eurlex ingest                          # download, parse, check, write units
    eurlex search "data breach" --lang pt  # try a query
    eurlex eval --rung 01_bm25 --split dev
    eurlex report                          # writes results/table.md
    docker compose up --build              # service + database

Run `eurlex --help` for the full option list.
