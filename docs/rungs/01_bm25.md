# Rung 01 - BM25 keyword search

Status: **implemented, not measured.** Code in `src/eurlex_rag/retrieve/bm25.py`,
tested on the synthetic corpus. No number exists until the real corpus (M1) and
the benchmark (M2) do.

## What it is

Classic keyword search. A chunk scores highly when it contains the query's
words, weighted so that rare words count for more, repeated words count with
diminishing returns, and long chunks are not favoured for being long.

The formula and the meaning of `k1` and `b` are in the module docstring. It is
written by hand, with no search library, so each step can be read.

## Why it is the baseline

- It is what search was before embeddings, and it is still hard to beat on
  queries that use the document's exact terms ("data protection officer",
  "Article 6").
- It costs almost nothing: no model, no GPU, microseconds per query.
- It has no notion of meaning or of language. A Portuguese question shares
  almost no words with an English article, so on cross-lingual queries it
  should fail. The size of that failure is the gap every later rung is trying
  to close.

## Two rows, not one

| Row | Query | Purpose |
|---|---|---|
| `01_bm25` | as typed, any language | Shows the raw language gap |
| `01_bm25_translated` | machine-translated to English first | The fair lexical baseline for non-English queries |

The second row needs a translation step, which arrives with the query
transformation work in M4. It is listed here so that nobody later compares
dense retrieval against the first row alone and calls the difference a win for
embeddings.

## Implementation notes

- Tokenisation: lower-cased runs of letters and digits. No stemming, no
  stop-word list. Both are worth trying on dev in M2 (stemming usually helps
  recall on legal English: "processing" / "processed"); record what was tried.
- Parameters default to `k1=1.5`, `b=0.75`. Tune on dev only.
- Chunking strategy (`article` vs `paragraph`) changes document length and
  therefore BM25's length normalisation. Evaluate both.
- PostgreSQL full-text search is the alternative mentioned in the spec. Its
  ranking function is not BM25; if it is compared, it is a separate row.

## Acceptance (milestone M2)

- `eurlex eval --rung 01_bm25 --split dev` and `--split test` produce result
  files, and `eurlex report` renders them.
- English Recall@5 is clearly above the non-English figures; if it is not,
  something is wrong with the benchmark (questions leaking the article's
  wording, or a parsing fault), and that is investigated before moving on.
